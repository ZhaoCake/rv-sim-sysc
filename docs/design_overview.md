# RISC-V单周期处理器TLM建模设计文档

## 1. 项目概述

本项目实现了一个基于SystemC的RISC-V单周期处理器的TLM（Transaction Level Modeling）模型。该模型可用于指令集仿真，以及后续在ESL方法学基础上进行RTL级的处理器设计和测试。

### 1.1 设计目标

- 实现RISC-V（RV32I）基本指令集的功能仿真
- 使用SystemC进行TLM级别的建模
- 提供清晰的模块化结构，便于未来扩展和RTL级实现
- 支持程序加载和执行
- 提供内存和寄存器状态的观察接口

### 1.2 系统架构

该处理器采用经典的单周期RISC-V架构，主要包含以下几个核心模块：

1. **取指（Fetch）模块** - 负责从内存中获取指令，更新程序计数器(PC)
2. **译码（Decode）模块** - 解析指令，生成控制信号
3. **执行（Execute）模块** - 执行ALU操作，处理分支和跳转逻辑
4. **寄存器文件（RegisterFile）模块** - 维护处理器寄存器组
5. **存储器（Memory）模块** - 提供指令存储器和数据存储器功能
6. **顶层（Top）模块** - 连接所有模块，形成完整的处理器

### 1.3 总体数据流

![处理器数据流](./images/dataflow.png)

数据流简述：
1. Fetch模块从Memory中获取指令
2. 指令被送到Decode模块进行解析
3. Decode模块生成控制信号，并读取寄存器值
4. Execute模块执行计算，并确定是否需要分支跳转
5. 内存访问（通过Memory模块）
6. 结果写回到寄存器文件

## 2. 系统集成

### 2.1 模块连接总览

各模块通过SystemC信号和接口进行连接，形成一个完整的单周期处理器流水线。顶层模块负责所有子模块的实例化和连接。

### 2.2 接口遵循原则

- 所有模块接口均使用标准SystemC信号类型
- 对外提供清晰的时钟和复位同步机制
- 各模块间使用标准的请求-响应模式进行通信
- 信号命名遵循统一的命名规范，便于理解和维护

### 2.3 关键路径

- 指令获取路径：PC->指令存储器->译码器
- 数据操作路径：寄存器读取->ALU计算->结果写回
- 控制流路径：条件评估->分支/跳转决策->PC更新

## 3. 实现策略

### 3.1 开发流程

1. 模块级功能设计
2. TLM模型实现
3. 单元测试验证
4. 系统集成测试
5. 指令集测试程序验证
6. RTL转换准备

### 3.2 测试策略

- 单元测试：独立测试每个模块的功能
- 集成测试：验证模块间接口正确性
- 系统测试：运行完整的RISC-V测试程序验证功能

### 3.3 扩展性考虑

- 模块化设计便于添加更多指令集扩展（如M、F等扩展）
- 清晰的接口定义允许未来扩展为多周期或流水线设计
- 与RTL实现保持一致的接口定义，便于未来的RTL转换

## 4. 使用指南

### 4.1 编译系统

项目使用Makefile管理编译流程，支持以下主要目标：
- `make` - 编译整个系统
- `make clean` - 清理编译产物
- `make test` - 运行测试
- `make run` - 使用默认程序运行模拟器

### 4.2 程序加载与运行

通过命令行参数控制模拟器行为：
```
./build/bin/riscv-sim --program <binary_file> --cycles <num_cycles>
```

支持的二进制程序格式与加载机制在Memory模块中实现。

### 4.3 调试功能

- 寄存器状态打印
- 存储器内容导出
- 周期级状态跟踪
